# LLD — AI Recruiter Copilot

Companion to `PRD_AI_Recruiter_Copilot.md`. This is the implementation spec
to hand to a coding agent (e.g. Antigravity) — folder layout, schemas, API
contracts, the LangGraph graph, and the exact prompts.

---

## 1. Architecture

```
React + Vite (frontend)
        │  axios (REST)
        ▼
FastAPI (backend)
  ├── /api/resume/upload      → save file, return resume_id
  ├── /api/resume/parse       → run Extractor node, return profile
  ├── /api/chat               → run Q&A node, return answer + evidence
  ├── /api/evaluate           → run full LangGraph pipeline (SSE/stream)
  ├── /api/dispatch/email     → (used internally by pipeline; also exposed for retry)
  ├── /api/candidate/{id}     → fetch stored profile
  └── /api/evaluation/{id}/download → stream generated PDF
        │
        ▼
LangGraph orchestration (in-process, not a separate service)
        │
        ▼
LLM Service (provider-agnostic: Gemini / OpenAI / OpenRouter via LLM_PROVIDER)
        │
        ▼
SQLite (candidates, evaluations, agent_runs)
```

**Reference repos worth borrowing concrete code from** (verified to exist —
see note at the end of this doc on the fabricated names from the earlier
brainstorm):

| Need | Repo | What to take |
|---|---|---|

| RAG-grounded resume Q&A (FAISS) | `Ajithbalakrishnan/LangGraph_Based_Resume_Screener` | Retrieval pattern if/when you outgrow single-document context (see PRD §9) |

None of these are drop-in — take the *pattern*, not a full clone, and
re-point them at the schema in §2 below.

## 2. Canonical Schemas (Pydantic)

```python
# schemas.py
from pydantic import BaseModel, Field
from typing import Optional, Literal

class Candidate(BaseModel):
    name: str
    email: Optional[str] = None
    phone: Optional[str] = None
    location: Optional[str] = None

class Education(BaseModel):
    institution: str
    degree: Optional[str] = None
    field: Optional[str] = None
    year: Optional[str] = None

class Experience(BaseModel):
    company: str
    title: str
    start_date: str          # "YYYY-MM"
    end_date: str             # "YYYY-MM" or "present"
    responsibilities: list[str] = []

class Skills(BaseModel):
    programming: list[str] = []
    frameworks: list[str] = []
    cloud: list[str] = []
    databases: list[str] = []
    tools: list[str] = []

class Project(BaseModel):
    name: str
    description: str
    evidence: Optional[str] = None

class EmploymentGap(BaseModel):
    period: str                                  # "2023-03 to 2025-01"
    status: Literal["unexplained", "explained"]
    reason: Optional[str] = None                  # only if resume states one

class CandidateProfile(BaseModel):
    candidate: Candidate
    education: list[Education] = []
    experience: list[Experience] = []
    skills: Skills = Skills()
    projects: list[Project] = []
    certifications: list[str] = []
    employment_gaps: list[EmploymentGap] = []
    years_of_experience: float
    raw_text: str

class QAAnswer(BaseModel):
    answer: str
    evidence: Optional[str] = None
    grounded: bool          # False if the model had to say "not specified"

class Evaluation(BaseModel):
    candidate_name: str
    email: Optional[str]
    primary_skillset: list[str]
    years_of_experience: float
    education: str
    employment_gaps: list[EmploymentGap]
    recommended_role: str
    evaluation_notes: str
    evidence: dict[str, str] = {}   # field_name -> supporting resume snippet
```

`years_of_experience` and `employment_gaps` are **computed in Python from
parsed dates**, then handed to the LLM as fact — never generated by the
LLM itself. This is the load-bearing anti-hallucination decision.

## 3. LangGraph Pipeline

```
START
  │
  ▼
[parse_node]        PDF/JSON → raw_text (PyMuPDF) → CandidateProfile (LLM structured extraction, dates/skills)
  │
  ▼
[compute_facts_node] Deterministic: years_of_experience, employment_gaps (pure Python, no LLM)
  │
  ▼
[qa_node]            (only invoked per /api/chat call, not part of the linear eval chain)
  │
  ▼
[evaluate_node]      LLM maps CandidateProfile → Evaluation draft (skills summary, recommended_role, notes)
  │
  ▼
[validate_node]      Pydantic-validate Evaluation
  │
  ├─fail──► [retry_node] (max 2 retries, re-prompt with validation errors) ──┐
  │                                                                          │
  └─pass───────────────────────────────────────────────────────────────┐    │
                                                                        ▼    ▼
                                                                  [document_node] → PDF (ReportLab)
                                                                        │
                                                                        ▼
                                                                  [dispatch_node] → mock/real SMTP, log to agent_runs
                                                                        │
                                                                        ▼
                                                                       END
```

State object passed between nodes (LangGraph `State` TypedDict):

```python
class GraphState(TypedDict):
    resume_id: str
    raw_text: str
    profile: CandidateProfile | None
    evaluation: Evaluation | None
    validation_errors: list[str]
    retry_count: int
    pdf_path: str | None
    dispatch_status: str | None
```

Each node emits a status event (`✓ Parsed resume`, `✓ Employment gap
detected`, etc.) over the `/api/evaluate` SSE stream so the frontend can
render the live checklist described in the PRD.

## 4. Prompt Templates

### 4.1 System prompt (shared by Q&A and Evaluate nodes)

```
You are an HR document analysis assistant.

You must answer using ONLY the candidate information provided below.

Rules:
1. Never invent candidate information.
2. If information is not present, respond exactly: "Not specified in the resume."
3. Do not infer or guess reasons for employment gaps — state the gap and stop.
4. Clearly distinguish documented facts from your own interpretation.
5. Cite the resume section or line that supports each answer, when possible.
6. Do not use any external or prior knowledge about this named candidate.
7. When asked to return JSON, return ONLY valid JSON — no prose, no markdown fences.
```

### 4.2 Q&A call

```
CANDIDATE DATA (structured):
{profile_json}

RESUME TEXT (raw):
{raw_text}

RECRUITER QUESTION:
{question}

Respond with JSON: {"answer": str, "evidence": str|null, "grounded": bool}
```

### 4.3 Evaluate call

```
CANDIDATE DATA (structured, includes computed years_of_experience and
employment_gaps — treat these as ground truth, do not recompute):
{profile_json}

Task: produce the HR evaluation JSON matching this schema exactly:
{evaluation_json_schema}

For "evidence", map each field you filled to the exact resume snippet that
supports it. If a field has no direct support, omit it from "evidence"
rather than fabricating a snippet.
```

### 4.4 Retry-on-validation-failure call

```
Your previous JSON output failed schema validation with these errors:
{pydantic_error_list}

Here is the same CANDIDATE DATA again:
{profile_json}

Return corrected JSON only, matching the schema exactly.
```

## 5. API Contracts

```
POST /api/resume/upload
  multipart/form-data: file
  → { "resume_id": "uuid" }

POST /api/resume/parse
  { "resume_id": "uuid" }
  → CandidateProfile

POST /api/chat
  { "resume_id": "uuid", "question": "string" }
  → QAAnswer

POST /api/evaluate            (Server-Sent Events stream)
  { "resume_id": "uuid", "dispatch_to_hr": true }
  → stream of {"step": "parse|compute_facts|evaluate|validate|document|dispatch", "status": "ok|error", "detail": "..."}
  → final event: { "evaluation": Evaluation, "pdf_url": "...", "dispatch_status": "SENT|MOCKED|FAILED" }

GET /api/candidate/{resume_id}
  → CandidateProfile

GET /api/evaluation/{evaluation_id}/download
  → application/pdf
```

## 6. Database (SQLite)

```sql
CREATE TABLE candidates (
  id TEXT PRIMARY KEY,
  profile_json TEXT NOT NULL,
  raw_text TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE evaluations (
  id TEXT PRIMARY KEY,
  candidate_id TEXT REFERENCES candidates(id),
  evaluation_json TEXT NOT NULL,
  pdf_path TEXT,
  dispatch_status TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE agent_runs (
  id TEXT PRIMARY KEY,
  candidate_id TEXT REFERENCES candidates(id),
  step TEXT NOT NULL,
  status TEXT NOT NULL,
  detail TEXT,
  timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 8. Validation & Retry Logic (key differentiator to call out in review)

```python
def evaluate_with_validation(profile: CandidateProfile, max_retries=2):
    errors = []
    for attempt in range(max_retries + 1):
        raw = llm_call(EVALUATE_PROMPT, profile, errors)
        try:
            return Evaluation.model_validate_json(raw)
        except ValidationError as e:
            errors = e.errors()
    raise EvaluationFailedError(errors)  # surfaced as a failed pipeline step, never silently swallowed
```
